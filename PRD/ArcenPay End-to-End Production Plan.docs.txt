## ArcenPay End-to-End Production Plan (Single GA, Full PRD Scope, 16-20 Weeks)

### Summary
- Deliver one public GA release covering full MEAP + ZKVUB + agent scope, with no production reliance on local/mock fallbacks.
- Keep `Clerk + SIWE wallet-link` as the dashboard auth model and harden it rather than replacing it pre-GA.
- Use `managed serverless` deployment, `Redis-backed workers` for async reliability, and `subgraph-first + RPC fallback` for read paths.
- Enforce GA gate: external security audit complete, zero unresolved critical/high findings, US+India invoice/tax baseline validated.

### Implementation Changes
- **Phase 1 (Weeks 1-2): Foundation hardening and source-of-truth cleanup**
- Define ownership boundaries: dashboard DB is source-of-truth for catalog/templates/invoices/audit; chain is source-of-truth for subscription/session state; facilitator is source-of-truth for x402 validation and operational delivery state.
- Remove all production runtime defaults that silently point to localhost, placeholder Graph URLs, or local-only fallback behavior.
- Fix identity consistency issues in audit payloads and team context usage so actor IDs are consistently DB user IDs + wallet addresses.
- Replace outdated/broken tests that still reference removed auth helpers and align test suites to current Clerk+SIWE flow.
- Freeze environment contract (required env vars) for dashboard, facilitator, subgraph, SDK consumers, and fail fast at startup in production profile.

- **Phase 2 (Weeks 3-7): Dashboard product completion**
- Unify catalog flow: author in dashboard catalog APIs, then publish with explicit chain sync status (including tx hashes and per-entity sync outcome).
- Complete templates lifecycle in UI and API: draft/edit/publish/install/version diff with explicit chain/environment compatibility checks.
- Finalize invoices domain UX and workflows: list/search/filter, status transitions, resend, signed download, credit notes, delivery timeline.
- Replace temporary/local settings persistence behavior with server-backed profile/settings storage only.
- Complete team operations: robust invite lifecycle, role enforcement across all mutating routes, and complete audit event coverage for every write action.
- Make environment switch a full safe operation: preflight contract readiness, explicit user confirmation, and post-switch UI/data segregation.

- **Phase 3 (Weeks 5-10): Facilitator reliability and billing pipeline**
- Move webhook + billing-event + usage-entry flows from best-effort/in-memory patterns to durable Redis/DB-backed queues with idempotency keys and replay tooling.
- Enforce strict x402 verification in production mode with replay protection, timestamp windows, settlement authorization checks, and deterministic rejection reasons.
- Complete proof orchestration hardening: strict-mode artifact verification, retry policy controls, duplicate/nullifier protection, and clear dead-letter handling.
- Make dashboard bridge resilient: authenticated integration, retry with backoff, durable error ledger, and operator-facing replay endpoints.
- Add operational health surfaces: queue depth, stale worker detection, settlement authorization status, proof runtime status, and dashboardable metrics/SLOs.

- **Phase 4 (Weeks 7-12): SDK and agent production readiness**
- Keep `@meap/core` contract/types as canonical SDK contract; add missing tests and semver policy for public API changes.
- Harden `@meap/react` for production embedding: configurable endpoints without localhost defaults, deterministic chain explorer links by chain, graceful degraded states, strict prop validation.
- Finalize `CheckoutModal` deployment path hierarchy and remove ambiguous fallback behavior; enforce explicit config requirements for smart-account deployment mode.
- Complete `FeatureFlagGuard` production path with clear backend-decrypt proxy contract and predictable fallback semantics.
- Harden `@meap/agent` flows: session funding, x402 negotiation, nonce/price guardrails, settlement observability, and failure handling suitable for autonomous runtimes.
- Publish migration notes and examples for integrators (dashboard API mode, facilitator mode, direct chain mode).

- **Phase 5 (Weeks 9-14): Chain rollout + subgraph + cross-chain**
- Deploy and validate Base Sepolia and Base mainnet contracts; remove zero-address placeholders from production chain registry.
- Add controlled chain promotion flow (Sepolia → Base mainnet) tied to environment mode and readiness checks.
- Complete MirrorRegistry transport hardening and deterministic fallback behavior between Axelar/CCIP paths.
- Upgrade subgraph production posture: start blocks, indexing health checks, reorg handling expectations, and analytics parity validation against on-chain reads.
- Add dashboard read-path policy: subgraph for analytics/aggregates, direct chain for user-critical entitlement/session correctness.

- **Phase 6 (Weeks 12-18): Security, compliance, performance, operations**
- Execute external audit cycle for contracts + facilitator + critical dashboard APIs.
- Add abuse-focused tests: permission escalation, webhook signature bypass, replay attacks, cross-tenant access, invoice token tampering.
- Implement US+India invoice/tax field completeness and formatting validation.
- Run load and soak tests for x402 endpoints, proof pipeline, webhook/email throughput, and invoice generation bursts.
- Finalize incident response package: runbooks, alert routing, on-call dashboards, disaster recovery drills (RPC outage, Redis outage, mail outage, queue backlog).

- **Phase 7 (Weeks 19-20): GA cutover**
- Freeze API and schema changes except blocker fixes.
- Run full dress rehearsal on production-like environment with real chain + queue + mail/webhook dependencies.
- Validate release gates and generate GA readiness report.
- Launch with rollback playbook, incident war-room readiness, and post-launch stabilization sprint.

### Public API / Interface / Type Changes (GA-targeted)
- Add publish-sync status contract to catalog publish API so each catalog entity reports on-chain sync result and failure reason.
- Add durable replay/admin endpoints for billing event processing and webhook delivery with strict auth + audit.
- Extend proof/ops endpoints with queue/dead-letter and worker-health metadata for operator dashboards.
- Standardize SDK response typing for invoices/templates/audit/events to avoid per-app shape drift.
- Lock deprecations: no breaking removals pre-GA; additive fields only, with explicit deprecation notices for fallback-only behavior.

### Test Plan and Acceptance Scenarios
- Contract E2E: provider registration, plan lifecycle, subscription mint/renew/cancel, autopay execution/revocation, session settlement, nullifier replay rejection.
- Facilitator E2E: x402 challenge/verify/settle path, nonce replay rejection, stale payment rejection, queue persistence through restart, webhook retry/replay.
- Dashboard E2E: onboarding (Clerk + SIWE), RBAC enforcement on all writes, environment switch guardrails, catalog publish + chain sync visibility, invoice send/resend/download.
- SDK E2E: react checkout flow on supported chains, feature guard behavior against facilitator backend, agent fetch+payment loop under price and nonce constraints.
- Data consistency checks: subgraph vs chain parity for critical counters/states, billing event idempotency, audit completeness for mutating actions.
- Performance/SLO checks: invoice generation success, webhook delivery latency/retry success, facilitator queue drain under burst load.
- Security checks: auth/session tampering, unauthorized API access, signature validation hardening, secret leakage checks in logs and responses.

### Assumptions and Defaults
- Single GA release remains the release strategy.
- Delivery window remains 16-20 weeks.
- Auth remains Clerk organizations + SIWE wallet linking for GA.
- Managed serverless infra, Redis-backed async workers, and subgraph-primary read strategy remain fixed.
- Compliance scope for GA is US + India only.
- External audit is mandatory before public GA.
- Post-GA expansions (fiat rails, broader token/chain support, advanced role builder) stay out of this release unless they become blockers.
